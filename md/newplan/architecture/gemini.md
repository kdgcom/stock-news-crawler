# 통합 개발 계획 및 아키텍처 제안 (Gemini 기반)

## 1. 개요 (Overview)

Codex, Claude, Gemini, Cursor의 제안을 종합하여, 실시간 주식 뉴스 및 데이터를 수집, 분석하여 사용자에게 유의미한 투자 정보를 제공하는 확장 가능하고 비용 효율적인 시스템을 구축하기 위한 최적의 개발 계획을 수립합니다.

## 2. 클라우드 플랫폼 추천 (Cloud Platform Recommendation)

**추천: Google Cloud Platform (GCP)**

### 선정 이유

| 기준 | GCP 선택 이유 |
|---|---|
| **비용 효율성 (Cost-Effectiveness)** | **서버리스 중심:** Cloud Functions, Cloud Run은 초기 및 유휴 비용이 거의 발생하지 않으며, 월별 상당한 무료 호출 횟수(Free Tier)를 제공하여 '무료 범위 내 서비스 구현' 목표에 가장 적합합니다. |
| **5년 장기 운영** | 트래픽 증가 시 자동 확장을 지원하므로, VM처럼 미리 용량을 과다하게 산정할 필요가 없어 TCO(총소유비용) 절감에 유리합니다. |
| **데이터 및 AI/ML 생태계** | BigQuery, Firestore, Vertex AI, Natural Language API 등 서비스 통합이 용이하여 향후 뉴스 분석, 감성 분석, 추천 모델 고도화에 유리합니다. |
| **경쟁사 대비** | AWS, Azure도 훌륭하지만, 사용자가 직접 언급한 '서버리스 무료 호출'과 초기 비용 최소화 측면에서 GCP가 가장 매력적인 선택지입니다. |

## 3. 데이터베이스 아키텍처 (Database Architecture)

**추천: 하이브리드 모델 (Hybrid Model)**

데이터의 성격에 따라 최적의 데이터베이스를 조합하여 사용함으로써 성능과 비용 효율성을 극대화합니다.

| 데이터 종류 | 대상 데이터 | 추천 서비스 | 선정 이유 |
|---|---|---|---|
| **Time-Series DB** | 주가(시/분/일), 거래량, 기술적 분석 지표 | **Google Cloud Bigtable** | 대량의 시계열 데이터를 빠르게 쓰고, 기간별로 조회/집계하는 데 최적화되어 차트 생성 및 백테스팅 성능을 보장합니다. |
| **NoSQL Document DB** | 뉴스 기사, 분석 리포트, 소셜 미디어 데이터, 감성 분석 결과 | **Google Cloud Firestore** | 비정형 텍스트 데이터를 스키마 없이 유연하게 저장하고, 전문(Full-text) 검색 기능으로 뉴스 콘텐츠를 쉽게 조회 가능합니다. |
| **RDBMS** | 사용자 정보, 구독 상태, 알림 설정, 관심 종목 등 정형화된 데이터 | **Google Cloud SQL** | 데이터의 일관성과 무결성이 중요한 사용자 관련 정보를 안정적으로 관리하고, 명확한 관계 설정에 유리합니다. |

## 4. API 및 처리 아키텍처 (API & Processing Architecture)

**추천: 서버리스 우선 접근 (Serverless-First Approach)**

| 계층 | 추천 기술 | 선정 이유 |
|---|---|---|
| **API 계층 (User-Facing API)** | **Google Cloud Functions / Cloud Run** | 트래픽이 불규칙한 사용자 요청을 처리하는데, 요청 시에만 실행되어 VM 대비 압도적으로 비용 효율적입니다. GCP의 넉넉한 무료 티어를 활용할 수 있습니다. |
| **데이터 수집/처리 계층 (Crawling & Processing)** | **Google Cloud Run & Cloud Scheduler** | 주기적 실행(Scheduler)과 긴 실행 시간(Run) 처리에 적합합니다. 작업이 없을 때는 인스턴스를 0으로 축소하여 비용을 최소화, VM의 유연성과 서버리스의 비용 효율성을 결합한 형태입니다. |

## 5. 종합 개발 계획 (Unified Development Plan)

### Phase 1: MVP (최소 기능 제품) 구축
1.  **인프라 설정:** GCP 프로젝트 생성, API 인증 설정, Cloud SQL/Firestore/Bigtable 데이터베이스 생성.
2.  **데이터 수집:** 특정 주식 뉴스 사이트를 대상으로 Python 웹 스크레이퍼 개발. Cloud Scheduler와 Cloud Run을 사용하여 1시간 주기로 실행 및 Firestore에 저장.
3.  **핵심 데이터 처리:** 수집된 뉴스의 제목과 본문을 Natural Language API를 통해 기본적인 감성 분석(긍정/부정/중립) 수행.
4.  **API 개발:** Cloud Functions를 사용하여 특정 종목의 최신 뉴스 및 감성 분석 결과를 조회하는 REST API 엔드포인트 구현.
5.  **프론트엔드(Optional):** 간단한 웹 인터페이스를 통해 API 결과 확인.

### Phase 2: 기능 고도화
1.  **데이터 소스 확장:** 더 많은 뉴스 소스, 소셜 미디어, 공시 정보 크롤링 추가.
2.  **분석 모델 개선:** 자체적인 추천 알고리즘 또는 ML 모델(Vertex AI)을 학습시켜 뉴스/종목 연관도, 중요도 분석 기능 추가.
3.  **데이터 시각화:** 주가 차트와 뉴스 타임라인을 함께 보여주는 프론트엔드 기능 개발.
4.  **사용자 기능:** 사용자 회원가입, 관심 종목 등록, 개인화된 뉴스 피드, 실시간 알림 기능 구현.

### Phase 3: 확장 및 운영
1.  **성능 모니터링 및 최적화:** Cloud Monitoring을 통한 시스템 상태 모니터링 및 병목 현상 개선.
2.  **백테스팅 시스템:** 과거 데이터를 기반으로 투자 전략을 테스트할 수 있는 기능 개발.
3.  **글로벌 서비스 확장:** 해외 주식 정보 수집 및 다국어 지원.
