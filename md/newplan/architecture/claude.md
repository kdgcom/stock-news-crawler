## 4. 클라우드 권고: GCP (Google Cloud Platform)

### 4.1 선정 사유

1. **무료 호출 한도 내 서비스 가능**: 월 2백만 요청 무료 → 본 시스템은 **월 5만 건 미만** (무료 한도의 2.5%)
2. **영구 무료 VM**: f1-micro 1대로 Redis, 스케줄러, WebSocket 리스너 등 상시 프로세스 운용
3. **5년 최저 비용**: 유일하게 유료가 되는 부분은 TimescaleDB용 Cloud SQL (~$10/월)뿐
4. **서울 리전**: KR 데이터 수집/증권사 API 호출 시 저지연
5. **Cloud Run의 유연성**: 컨테이너 기반이라 Python + 복잡한 의존성(PyTorch, LightGBM 등) 배포 용이

## 5. 데이터베이스 설계 권고

### 5.1 혼합 DB 전략 (4개 기획안 공통 합의)

4개 LLM 기획안 모두 **단일 DB가 아닌 혼합 구성**을 제안하고 있으며, 이는 올바른 접근이다.

```
┌─────────────────────────────────────────────────────────────────┐
│                         Storage Layer                           │
│                                                                 │
│  ┌──────────────┐  ┌──────────────────┐  ┌──────────────────┐  │
│  │  MongoDB      │  │  TimescaleDB     │  │  Redis           │  │
│  │  (NoSQL)      │  │  (Time Series)   │  │  (Cache/Stream)  │  │
│  │              │  │                  │  │                  │  │
│  │  • raw_news   │  │  • market_1m_bars│  │  • 실시간 상태    │  │
│  │  • enriched   │  │  • decision_logs │  │  • 최근 N분 캐시  │  │
│  │  • NER 결과   │  │  • 기업 마스터    │  │  • 이벤트 스트림  │  │
│  │  • 감사 원문   │  │  • 백테스트 결과  │  │  • 포지션/PnL    │  │
│  └──────────────┘  └──────────────────┘  └──────────────────┘  │
│   유연한 스키마        SQL 쿼리 + 시계열     저지연 읽기/쓰기     │
│   ~10GB/년            ~20GB/년             ~100MB 상시          │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 각 DB 선정 근거

#### MongoDB (NoSQL) — 뉴스/이벤트 저장

| 항목 | 판단 |
|------|------|
| **왜 RDB가 아닌가** | 뉴스 데이터는 소스마다 필드가 다르고, NER/토픽/감성 등 분석 결과가 점진적으로 추가됨. 고정 스키마는 잦은 ALTER TABLE을 유발 |
| **왜 MongoDB인가** | 문서형 구조가 JSON 뉴스 데이터와 자연스럽게 매핑. `event_id` 기반 upsert 네이티브 지원. 4개 기획안 모두 MongoDB 선택 |
| **GCP 배포** | MongoDB Atlas M0 (무료, 512MB) → M2 ($9/월, 2GB) → M5 ($25/월, 5GB) |
| **대안** | Azure Cosmos DB (MongoDB API 호환, 25GB 영구 무료) — 멀티클라우드 허용 시 최적 |

#### TimescaleDB (Time Series DB) — 시세/로그 저장

| 항목 | 판단 |
|------|------|
| **왜 일반 RDB가 아닌가** | 1분봉 데이터는 시간 기반 범위 쿼리가 핵심. 일반 PostgreSQL은 수억 행에서 성능 저하. TimescaleDB의 hypertable은 자동 시간 파티셔닝으로 10~100배 빠른 시계열 쿼리 제공 |
| **왜 InfluxDB가 아닌가** | TimescaleDB는 PostgreSQL 확장이므로 SQL 완전 지원. JOIN, 윈도우 함수, 트리거 등 RDB 기능을 그대로 사용 가능. 의사결정 로그, 기업 마스터 데이터도 같은 DB에 저장 가능 |
| **핵심 이점** | **RDB + Time Series DB를 하나로** — 운영 복잡도 감소 |
| **GCP 배포** | Cloud SQL PostgreSQL (db-f1-micro, ~$10/월) + TimescaleDB 확장 설치 |

#### Redis — 캐시/스트림/실시간 상태

| 항목 | 판단 |
|------|------|
| **역할** | ① 최근 N분 시세 캐시 (저지연 조회) ② Redis Streams (이벤트 버스) ③ 실시간 포지션/PnL 상태 ④ 중복 뉴스 체크 (Bloom Filter) |
| **왜 별도 DB인가** | MongoDB/TimescaleDB는 ms 단위 실시간 조회에 부적합. Redis는 인메모리로 <1ms 응답 |
| **GCP 배포** | f1-micro VM 내 직접 운영 (MVP) 또는 Upstash Redis 무료 (256MB, 50만 명령/월) |

### 5.3 DB 데이터 흐름

```
뉴스 수집 ──→ MongoDB (raw_news_events)
                │
                ▼
           분석/NLP 처리
                │
                ▼
          MongoDB (enriched_news_events) ──→ Redis (최근 감성 캐시)
                                                    │
시세 수집 ──→ TimescaleDB (market_1m_bars) ──→ Redis (최근 N분 캐시)
                                                    │
                                                    ▼
                                            Signal Aggregator
                                                    │
                                                    ▼
                                         TimescaleDB (decision_logs)
```

## 6. API 아키텍처: 서버리스 + VM 하이브리드

### 6.1 왜 순수 서버리스도, 순수 VM도 아닌가

| 방식 | 장점 | 이 시스템에서의 한계 |
|------|------|---------------------|
| **순수 서버리스** | 유휴 시 비용 $0, 자동 스케일 | WebSocket 연결, Redis Streams 소비자 등 상시 프로세스 불가. Cold start 지연 |
| **순수 VM** | 상시 프로세스 가능, 유연함 | 유휴 시간에도 비용 발생. GCP 무료 VM(f1-micro)은 0.6GB RAM으로 제한적 |
| **하이브리드** | 양쪽 장점 조합 | 약간의 아키텍처 복잡도 증가 |

```

  │     └── POST → Cloud Run [kr-price-collector]
```

## 8. 멀티클라우드 대안 (비용 극한 최적화)

GCP 단일 클라우드가 운영 단순성 측면에서 권장되지만, **비용을 극한까지 줄이려면** 다음과 같은 멀티클라우드 조합도 가능하다.

| 역할 | 서비스 | 비용 |
|------|--------|------|
| 컴퓨팅 | GCP Cloud Run | $0 |
| 상시 VM | GCP f1-micro | $0 |
| 뉴스 DB | **Azure Cosmos DB** (MongoDB API, 25GB 영구 무료) | **$0** |
| 시계열 DB | GCP Cloud SQL + TimescaleDB | $10/월 |
| Redis | Upstash (256MB, 50만 명령 무료) | $0 |
| **합계** | | **$10/월** |

> Cosmos DB 25GB면 뉴스 데이터 2.5년치를 무료로 저장 가능. 다만 GCP↔Azure 간 네트워크 지연(~50ms 추가)이 발생하므로 실시간 성능이 중요한 시세 데이터에는 적합하지 않다. 뉴스 데이터는 실시간성이 덜 중요하므로 허용 가능.

## 10. 의사결정 요약

### Q1: Azure, AWS, GCP 중 어떤 것?

**→ GCP**. 가장 넓은 영구 무료 티어(Cloud Run 2백만 요청, f1-micro VM), 서울 리전, 컨테이너 기반 서버리스(Cloud Run)가 Python ML 워크로드에 적합하다. 5년 TCO가 가장 낮다.

### Q2: DB는 어떤 것?

**→ 세 가지 혼합**.

| DB | 용도 | 선택 사유 |
|----|------|----------|
| **TimescaleDB** (PostgreSQL 확장) | 시세 1분봉, 의사결정 로그, 기업 마스터 | RDB의 SQL 능력 + 시계열 최적화를 하나로. 시간 파티셔닝 자동화. |
| **MongoDB** | 뉴스 원문, 분석 결과, NER, 감사 원문 | 유연한 스키마로 다양한 소스/분석 결과 수용. event_id upsert 네이티브. |
| **Redis** | 캐시, 이벤트 스트림, 실시간 상태 | 인메모리 <1ms 응답. Redis Streams로 이벤트 버스 역할까지. |

### Q3: 서버리스 vs VM?

**→ 하이브리드**. 서버리스(Cloud Run)를 주축으로 하되, 상시 프로세스용 VM 1대를 병행한다.

| 컴포넌트 | 배포 방식 | 사유 |
|---------|---------|------|
| 데이터 수집 (뉴스/시세) | Cloud Run (서버리스) | 주기적 burst → 유휴 시 비용 $0 |
| 분석/신호 엔진 | Cloud Run (서버리스) | 이벤트 트리거, 무상태 |
| 리스크 체크 | Cloud Run (서버리스) | 주문 전 1회 호출 |
| Redis / 스트림 소비자 | f1-micro VM (상시) | 상시 연결 필요 |
| WebSocket 리스너 | f1-micro VM (상시) | 실시간 시세 수신 |
| 스케줄러 | Cloud Scheduler + VM 보조 | cron 트리거 |

### Q4: GCP 무료 범위 내 구현 가능한가?

**→ 컴퓨팅은 가능, DB는 일부 유료**.
- Cloud Run: 월 5만 건 << 무료 한도 200만 건 → **완전 무료**
- f1-micro VM: **영구 무료**
- TimescaleDB (Cloud SQL): **~$10/월 유료** (이것이 유일한 필수 유료 항목)
- MongoDB Atlas M0: 무료 (512MB까지)
- Redis: VM 내 운영 또는 Upstash 무료

**MVP 단계 실질 비용: 월 $10 (Cloud SQL TimescaleDB만 유료)**
