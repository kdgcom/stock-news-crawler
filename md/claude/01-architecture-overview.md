# AI 기반 주식 트레이딩 시스템 - 아키텍처 개요

## 1. 시스템 목표

국내(KRX) 및 미국(NYSE/NASDAQ) 주식 시장을 대상으로:
- 실시간 뉴스 크롤링 및 감성 분석
- 실시간 주가 데이터 수집 및 기술적 지표 계산
- AI Agent를 통한 매수/매도 의사결정
- 증권사 API를 통한 자동 주문 실행

을 수행하는 **엔드투엔드 자동 트레이딩 시스템**을 구축한다.

## 3. 기술 스택 선정

| 영역 | 기술 | 선정 이유 |
|------|------|-----------|
| **언어** | Python 3.11+ | 금융 라이브러리 생태계, AI/ML 지원, 증권사 API 샘플 코드 |
| **메시지 큐** | Redis Streams | 경량, 실시간 이벤트 처리, 시계열 데이터에 적합 |
| **데이터베이스** | MongoDB (기존) + TimescaleDB | 뉴스(비정형) → MongoDB, 시세(시계열) → TimescaleDB |
| **AI/LLM** | Claude API / OpenAI API | 뉴스 감성 분석, 요약, 투자 의견 생성 |
| **태스크 스케줄러** | APScheduler / Celery | 주기적 크롤링, 배치 처리 |
| **웹 프레임워크** | FastAPI | 대시보드 API, 웹훅 수신 |
| **모니터링** | Grafana + Prometheus | 시스템 메트릭, 트레이딩 성과 시각화 |
| **알림** | Slack / Telegram Bot | 매매 신호, 에러 알림 |

## 5. 데이터 흐름

### 5.1 뉴스 기반 트레이딩 흐름

```
뉴스 발생 → 크롤러 수집 → 감성 분석 (LLM) → 시그널 생성 → 리스크 체크 → 주문 실행
                                                    ↑
                                        기술적 지표 + 재무 데이터
```

1. **뉴스 수집**: 크롤러가 네이버 금융, 한경, SEC 등에서 뉴스를 수집
2. **감성 분석**: LLM이 뉴스의 긍정/부정/중립을 판단하고 영향 점수 산출
3. **시그널 생성**: 감성 점수 + 기술적 지표 + 재무 데이터를 종합하여 매수/매도 시그널 생성
4. **리스크 체크**: 포지션 한도, 손절 라인, 일일 거래 한도 등 검증
5. **주문 실행**: 증권사 API를 통해 실제 주문 전송

### 5.2 시간 축 기준 처리 주기

| 주기 | 처리 내용 |
|------|-----------|
| **실시간** (WebSocket) | 시세 수신, 호가 수신, 체결 알림 |
| **1분 간격** | 뉴스 속보 크롤링, 기술적 지표 갱신 |
| **5분 간격** | 뉴스 감성 점수 종합, 시그널 재평가 |
| **1시간 간격** | 포트폴리오 리밸런싱 검토 |
| **장 시작 전** | 전일 공시/뉴스 분석, 관심 종목 업데이트 |
| **장 마감 후** | 일일 성과 리포트, 다음 날 전략 수립 |

## 6. 개발 단계별 로드맵

### Phase 1: 데이터 수집 기반 구축 (현재 프로젝트 확장)
- 국내/미국 뉴스 크롤러 완성
- 실시간 시세 수집 파이프라인 구축
- MongoDB 스키마 확장, TimescaleDB 연동

### Phase 2: 분석 엔진 구축
- LLM 기반 뉴스 감성 분석 엔진
- 기술적 분석 지표 계산 모듈
- 재무 데이터 분석 모듈

### Phase 3: AI 트레이딩 에이전트
- 매매 시그널 생성 로직
- 포트폴리오 최적화
- 리스크 관리 시스템

### Phase 4: 실행 및 모니터링
- 증권사 API 연동 (모의투자 먼저)
- 대시보드 및 알림 시스템
- 백테스팅 프레임워크

### Phase 5: 고도화
- Multi-Agent 아키텍처로 전환
- 강화학습 기반 전략 최적화
- 실전 투자 전환 (단계적 자금 투입)

## 7. 핵심 설계 원칙

1. **모의투자 우선**: 모든 전략은 반드시 모의투자에서 충분히 검증 후 실전 적용
2. **점진적 확장**: 단순한 규칙 기반 → LLM 보조 → 완전 자동화 순서로 발전
3. **리스크 최우선**: 어떤 상황에서도 리스크 관리 모듈이 최종 결정권을 가짐
4. **감사 추적성**: 모든 의사결정과 거래는 근거와 함께 기록
5. **장애 대응**: 시스템 장애 시 모든 미체결 주문 자동 취소, 안전 모드 전환
